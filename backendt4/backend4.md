# 理论题组

1. Linux内核与发行版

    - Linux内核(Kernel)指的是由Linus Torvalds等人开发并维护的系统底层驱动和控制程序，没有图形界面，普通用户无法直接操作。Linux内核是开源的。
    - Linux发行版(Distribution)是由其他个人或厂商开发、基于Linux内核的系统版本，它有图形界面，安装有基本的应用程序，可供用户直接操作。
    - 如果用比喻形容，Linux内核就像毛坯房，不能直接住，但具备住房的最基本条件；发行版则是经过装修、能保障正常生活的精装房。

2. 根目录下的文件夹

    - 根目录下的文件夹及其作用：

    |名称|作用|
    |---|---|
    |bin|存放最基础的命令|
    |sbin|系统管理员用的命令|
    |lib/lib64|存放程序运行需要的函数库|
    |usr|包含绝大多数的软件、库文件等，类似于/Program Data|
    |home|普通用户家目录，存放个人文件|
    |root|管理员的家目录|
    |tmp|存放运行时产生的临时文件|
    |var|存放经常变化的数据，如系统日志|
    |etc|存放系统的所有配置文件，要改设置就来这里|
    |boot|存放系统启动相关的文件|
    |dev|存放设备对应的文件|
    |media|可移动设备的挂载点|
    |mnt|手动或自动挂载文件的挂载点|
    |proc|属于虚拟文件系统，用于查看进程信息|
    |sys|疏雨虚拟文件系统，用于检测或修改硬件信息|
    |run|存放系统运行时的临时数据|
    |lost+found|当文件系统崩溃后，重启时进行磁盘检查，恢复出来的残缺文件会放在这里|
    |srv|存放一些网络服务的数据|
    |opt|存放第三方可选软件，有些软件安装时默认装在这里|
    |snap|Ubuntu独有的目录，存放通过snap安装的软件|

    - 至于我自己的文件，如我为了测试文件读写而创建的文件，应该保存在/home/(我的user name)中。


3. “一切皆文件”思想
    > “一切皆是文件”是 Unix/Linux 的基本哲学之一，它是指 Linux 系统中的所有的一切都可以通过文件的方式访问、管理，即使不是文件，也以文件的形式来管理。例如硬件设备、进程、套接字等都抽象成文件，使用统一的用户接口，虽然文件类型各不相同，但是对其提供的却是同一套操作。

    怎么去理解呢？打个比方，Linux中有七种基本的文件类型，他们就像家中的空调、电视、扫地机器人，都要使用遥控器操控（与文件交互的接口）。“一切皆文件”的思想，赋予了我们一把万能遥控器，无论想操控哪种电器都可以按相同的按：“启动”键可以使任何家电开启，“上”键用在电视就是调音量，用在空调就是调温度——这极大地简化了我们对它们的操控。作为开发者，这也赋予了我们更多的操作空间：我们可以通过编写shell脚本来直接控制硬件，如显示器亮度；也可以组合起不同类型的文件，实现一些独特的效果。

4. Vim
    Vim是一个令新手 ~~(including me)~~ 望而生畏的文本编辑器，由一个古老的文本编辑器Vi发展而来。它的特点：

    - 安装Linux时自带
    - 纯键盘操作
    - 模式化编辑，不同模式下点击按键的效果不同

    要陈述其用法，首先要弄明白它的几种模式：

    |模式|作用|怎么进入|
    |---|---|---|
    |命令模式(normal)|默认的模式，可以移动光标、删除、复制粘贴，但不能直接输入文本|打开vim默认就是，在其他模式下按`Esc`即可回到这个模式|
    |插入模式(insert)|用来编辑文本，就像普通的记事本一样。|在命令模式下输入`i`或`a`等|
    |底行模式(Command-line)|用于执行命令，如保存、退出、查找|在命令模式下按`:`|

    基础操作：

    - 移动光标用k/j/h/l，分别对应上/下/左/右；`0`跳到行首，`$`跳到行尾；`w`跳到下一个单词开头，`b`跳到上一个单词开头
    - `i`在光标前插入，`a`在光标后插入，对应的分别是"insert"和"append"的意思
    - `x`删除光标后的一个字符，`dd`删除整行，`dw`删除光标后的一个单词。
    - `yy`复制整行，`p`在光标后粘贴。
    - `u`撤销，`Ctrl+r`撤回撤销。

# 实践

1. 安装
    我根据[官方网页](https://learn.microsoft.com/zh-cn/windows/wsl/install)进行了WSL其在它上面的Ubuntu的安装。
2. 学习并尝试使用Linux常用命令，我的操作如下：

    - 在输入命令之前，我首先学习`Ctrl + ins`是复制文本，`Shift + ins`是粘贴文本。
    - 接着，我用`pwd`查看当前目录；
    - 用`ls`查看目录下文件；用`ls -la`查看所有文件及其信息；
    - 用`mkdir`创建实验目录；
    - 用`cd`进入目录；
    - 用`touch`创建文件；
    - 用`echo`写入内容，用`cat`查看；
    - 用`cp` `mv` `rm`分别测试了文件的复制、移动、删除；
    - 用`chmod 600`修改了文件权限；
    - 用`df -h`查看磁盘，用`free -h`查看内存，用`ps aux | head`查看进程，用`uptime`查看系统运行时间。
    - 用`sudo apt install ufw`安装ufw，用`sudo ufw status`查看防火墙状态。

4. WSL的网络

    （这个环节真的学不明白，只是一知半解，已经很努力在理解了）
    - 作为在Windows环境中运行的一个子系统，默认状态下访问互联网时并不与Windows用同一套网络地址和网关。默认状态下，WSL2(也就是现代的WSL)使用的网络模式是NAT(网络地址转换)，这个模式下WSL会创建一个虚拟网卡，并有一个独立的IP地址(与Windows系统的不同)。
    - HOST网络模式是另一个概念。Host就是宿主机，在这个模式下，WSL就像和Windows系统连成一体一般(而NAT模式更像是WSL是运行在Windows内部的另一个系统)，不要给这个程序单独准备一套网络环境，让它直接使用 Host 的网络环境。

5. WSL的运行原理

    现代的WSL，即WSL2，与其他虚拟机不同，它不是从硬件上开始模拟，模拟出一个完整的计算机，而是使用了虚拟化技术，提供一个非常轻量的环境给 Linux 内核运行：这就是为什么WSL2运行效率比较高。

    举个例子，其他虚拟机若要调用8GB内存，那么计算机中实实在在的8GB内存就被分配给它，再也要不回来；而在WSL2中，分配的内存还可以被动态回收给Windows。

6. 系统代理
    要让 WSL（Windows Subsystem for Linux）命令行中的应用走 Windows 系统代理，最现代且简便的方法是开启 WSL 的自动同步代理与镜像网络模式。

    我配置了一个.wslconfig文件在`C:/user/<我的用户名>`中，内容是：

    ```text
    [wsl2]
    networkingMode=mirrored
    dnsTunneling=true
    autoProxy=true
    ```

    这就开启了WSL的另一种网络模式：镜像模式，直接让WSL跟Windows共用网络。这样一来，`ping google.com`就可以实现了。
