## 整数溢出

这是我两次测试得到的结果：
![整数溢出.png](https://img.cdn1.vip/i/6ab482895c6bb_1790214793.webp)
第一个测试的结果在下面，因为我使用double类型存储输入的数字，所以可以保存1.8e37大小的数值，没有报错；

而第二个测试的结果在上面，我另写了一个程序输出LONG.MAX_VALUE，也就是long类型能保存的最大值加1，结果当然是出现了问题。

问题的原因在于这其中出现了整数溢出：long类型在计算机中占8个字节，也就是64位，因此最大可保存大小为$2^{63}-1$的数值：二进制的64个数位中第一位用来表示正负，其余用于计数。因此，LONG.MAX_VALUE就等价于$2^{63}-1$。当我试图把这个数加1，此时long类型的变量占用的字节就不够用来计数了，于是这个long值就会溢出，其占用的字节就会变为1000...0(63个0)，也就是$-2^{63}$。

解决方法：从Java 8开始，Math类中就有一种方法检测是否出现整数溢出问题。

```Java
Math.addExact(int a, int b)        // 加法，long类型也适用
Math.subtractExact(int a, int b)   // 减法
Math.multiplyExact(int a, int b)   // 乘法
```

一旦出现溢出，可以立马抛出错误报告。

## 浮点数误差

这是我写的程序跑出来的结果：
![浮点数误差.png](https://img.cdn1.vip/i/6ab48292dde87_1790214802.png)

由此可见，0.01连加100次，答案竟然不是1。其原因就是浮点数有误差：当我们试图将0.5/0.25这类数转换为二进制时，得到的是一个有限小数；但当我们试图将0.01转化为二进制存放在字节中，我们转换得到的是一个无限小数。这导致了用float或double类型的变量存放这类小数，存放下来的是二进制下该数字保留下来的有限位，而非完全精确的十进制数0.01。因此，运算时难免出现误差。

而由于double类型的变量能保留的二进制小数位数更多，因此用double类型的变量进行运算时，浮点数误差更小，不过依然存在。

# 9/24下午修改

1. 初次做题时犯了没有认真读题的错误，把我的计算器程序改正后，这次它实现的是两个long整数之间的运算，从而验证了9e18+9e18出现了整数溢出的错误。
    ![](https://img.cdn1.vip/i/6ab4d8f99391c_1790236921.png)
2. 思考过后，我想出了不用math类方法也能判断整数溢出的方法：
    - 判断加法溢出的方法如下：

    ```java

    long firstNumber = scanner.nextLong();
    long secondNumber = scanner.nextLong();
    if(firstNumber > LONG.MAX_VALUE - secondNumber)
    {
        //报错
    }
    ```

    乘法也是同理。

    - 减法的溢出只会发生在两个数异号时，故判断是否同号再判断其大小(与加法类似)即可。
    - 整数除法的溢出有且仅有一种情况：$-2^{63}/-1$，也就是`LONG.MIN_VALUE`取负。进行特判即可。
