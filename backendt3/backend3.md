## Git

Git是一个开源的软件，一个**命令行工具**。它离线运行在本地计算机上，用于管理数据(文档、代码、日志等)**版本**的实用工具。使用它的目的显而易见：可以很方便的读取之前版本的数据。

比方说，我想做一个产品，最初版觉得不好，之后改了半天发现还不如最初版，这时便可以利用Git保存的旧版本；再举个例子，假如我是个游戏开发者，我做好游戏的1.7版本三个月后发行了它，此时我早就在开发游戏的2.0版本了，可是这个时候突然有玩家反映1.7版本有严重bug，这个时候我就可以利用Git保存的1.7版本赶快修复掉这个bug，发布1.7.1漏洞修复版本，也不会太耽误我开发2.0版本。

## Github

Github是一个在线网页，是一个**基于Git的云端数据托管平台**，同时也是一个开发者社交与协作的平台。如果说Git是在本地保存和处理数据版本，那么GitHub便将数据**上传至云端**。这样一来可以不必担心本地数据遭到损毁，二来也可以在线与其他开发者协作。

## 二者的关系

- GitHub是基于Git运行的。没有Git，就没法用GitHub上传数据版本。
- Git负责的是**记录、保存**并管理数据的变化，而GitHub负责的是将这些数据及其变化**上传到云端**。打个比方：
    Git就像游戏的存档/读档器，GitHub就像云存档系统，而且能让其他玩家一起建设这个存档。

## Git's Significance

在上文中已经举出例子进行说明。举出的两个例子就代表了Git发挥作用的两个场景。而这时又有一种观点：既然使用Git是为了保存之前的程序或文档版本，那为什么不直接备份下来整个数据包呢？这种方法和用Git管理版本的最大区别就是：**Git更注重“改动”。** 当我发现1.6.1没有某个Bug，而1.6.2有，我就知道也许是这次改动中的某些代码是有问题的，或与之前的代码产生了“不良反应”。
