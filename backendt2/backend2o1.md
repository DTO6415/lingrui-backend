# 关于协议

在我看来：协议就如同它的字面意思，是一种规定，规定了客户端与服务端之间如何传输数据。

比方说，我要在vscode里写markdown文件并使它渲染preview，实际上就是我在与vscode进行信息交流。我们需要规定好，用双星号包住文本表示**加粗**，用单星号包住表示*斜体*等等。倘若我们没有这份“协议”，那么我写下文字打开preview，也就是将数据传输给它，它不知道这些数据代表着什么，因此就不能成功渲染。

协议的必要性在此就体现出来了：有了一种协议，无论是什么客户端和服务端，传输的是什么数据，只要都遵循同种协议，彼此就能互相看懂对方想要干什么，也就能高效地做出相应的发送请求、作出回应的行为。

如上指的是客户端和服务端之间信息交流需要协议(如http协议)的必要性，其他协议也是类似，不过是目的不同(如机器之间建立联系、数据传输寻找目的地)。

# 抓包实验

0. 我对标头(Header)的理解：假如信息交流是寄送快递，那么标头就是快递包裹上的寄件人、收件人、取件码、单号等信息。它们不被看做寄送的快递内容(信息)本身，但是属于不可或缺的附加信息。
1. 常规(General)中：
   - 请求方法(Method):POST。请求方法代表着这次请求的目的是什么。常见的method及其代表的意图如下：

       | Method | meaning |
       | --- | --- |
       | POST | 提交 |
       | GET | 获取 |
       | PUT | 整体更新 |
       | PATCH | 局部更新 |
       | DELETE | 删除 |

   - 状态码(Status Code):200。状态码代表着这次请求结果如何。常见的状态码及其代表的结果如下：

       | Status Code | meaning |
       | --- | --- |
       | 200 | 请求成功 |
       | 301 | 永久重定向 |
       | 302 | 临时重定向 |
       | 400 | 请求有误 |
       | 403 | 无权限 |
       | 404 | 资源不存在 |
       | 500 | 服务器错误 |
       | 502 | 网关错误(上游服务器响应无效) |
       | 451 | 因法律原因不可用 |

2. 请求标头中(举三个例子):

    - Accept:发送者希望得到的响应的类型，如html,json.在我的实验中，它呈现为:

    ```text
    application/json, text/plain, */*
    ```

    代表着发送者最希望得到JSON，其次希望得到纯文本格式，最后"\*/\*"代表哪怕发来的不是这两种类型也不会拒绝请求。

    - Origin:类似于“寄件人”，解释了发送者是谁。在我的实验中，呈现为：

    ```text
    https://lingrui.studio
    ```

    - User-Agent:指明了寄件人所处的客户端是什么。在我的实验中，呈现为：

    ```text
    Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/153.0.0.0 Safari/537.36 Edg/153.0.0.0
    ```

    这其中，"Edg"是我使用的Edge浏览器的身份标识。

3. 响应标头中：
    是有Set-Cookie的。在我的实验中，呈现为：

    ```text
    你不会真的想看我的登录token吧？
    ```

    开个玩笑。这个部分的意思就是，服务端告诉客户端，“这就是cookie，把它存起来。”

    什么是cookie？简单来说，cookie就是一小段保存在客户端中的信息，当客户端执行某些操作时，能够直接把这段信息发送给服务端，从而实现保留用户某些信息和使用偏好等的功能。例如，在我的实验中我看到的有：

    - recruit_token:登录用的token，保留着我的登录信息。
    - Max-Age:这个cookie最多能保存多少秒。这代表这个cookie什么时候过期。
    - Expires:直接规定了这个cookie在哪个时间节点过期。与上一个内容的用途相同。
    - Path:规定了这个cookie在这个网站的哪个路径下有效。如果说显示为"Path=/"，表示它在这个网站所有子路径下都有效。
    - HttpOnly:不同于上述内容呈现为“键=值”的形式，它单独出现，只要出现就代表了"true"，也就是开启这个功能。它的用处主要是限制了JavaScript读取cookie的内容，防止恶意脚本读取登录信息，造成安全问题。

4.  
    - “负载”选项卡中，显示的是类似这样的一串字符：

    ```text
    {"identifier":"bugeinikan","password":"bugeinikan"}
    ```

    这就是发送登录请求时客户端向服务端发送的登录信息。

    - “响应”选项卡中，显示的是类似这样的一段代码：

    ```JSON
    {
        "code": 0,
        "data": {
            "userId": "像身份证号一样的一串数字",
            "account": "DTO6415",
            "roles": [
                "MEMBER"
            ],
            "roleNames": [
                "MEMBER"
            ]
        }
    }
    ```

    这就是服务端确认登录后发送给客户端的我的用户信息。

5. cookie:其实我刚刚已经解释过cookie的内容了，现在我回答一下问题：

    HttpOnly被勾选了，Secure和SameSite没有被勾选。Secure如果被勾选，则这个cookie只能用HTTPS加密协议运输，确保了其安全性；SameSite用于控制跨站运输的请求。不被勾选，意味着如果是安全的请求，比如输入lingrui.studio打开网页，则浏览器会把cookie带过去；假如是危险的跨站请求，则浏览器不会将其带过去。
